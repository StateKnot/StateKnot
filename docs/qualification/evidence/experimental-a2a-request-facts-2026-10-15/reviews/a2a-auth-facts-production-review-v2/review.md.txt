## Standards

**0 actionable findings** in the frozen production patch.

Applied the user-provided production-grade instructions, the repository's
[contribution rules](context/CONTRIBUTING.md), [RFC lifecycle](context/docs/rfcs/README.md),
workspace MSRV/unsafe policy, and mattpocock code-review smell baseline and
codebase-design principles. No repository `AGENTS.md` was present; the supplied
user instructions still apply.

The existing authorization Interface is the real Seam. Three read-only getters
add the facts an existing Adapter needs without adding a second policy trait,
public wire-SDK types, dependencies, or a second serializer. The private
`A2aHttpRequest` gathers method, URL, body and streaming selection in the same
place and is consumed by the HTTP builder. Its deletion would reintroduce
parallel argument lists and possible authorization/send drift. The two call
paths still have distinct response processing; extracting a larger transport
framework for their short snapshot construction would add speculative scope.

This remains experimental work under Draft RFC-0025. The patch does not change
its status to Accepted or satisfy the remaining implementation, test,
documentation and release requirements for adoption.

## Source checks and limits

| Concern | Finding and precise scope |
| --- | --- |
| Exact method / URL / body | Unary and streaming paths select the binding, construct the actual REST URL/query or JSON-RPC envelope, serialize once, enforce the existing byte limit, then create the snapshot before `resolve_authorization`. The provider sees a clone of that snapshot; the original is moved into the builder. There is no later application rewrite or second serialization. |
| URL/query identity | `rest_url` starts from the immutable selected interface, adds percent-encoded path segments, and the read/list operations finish query pairs before the snapshot. JSON-RPC uses the selected interface URL. `request_url()` returns this normalized `Url` serialization, not the original unparsed spelling or a DNS/TLS peer attestation. It includes query data, including page tokens; do not log it. |
| reqwest URL consumption | Locked reqwest `Client::request` moves an owned `Url` through `IntoUrl` into `Request::new`. The builder's authority extraction would remove URL userinfo, but `parse_a2a_url` already rejects it; fragments and configured-base queries are rejected as well. Dynamic operation queries survive. Existing shared HTTP client disables redirects and retries. This does not make system proxy, DNS, or remote server behavior part of an authorization proof. |
| Payload identity / copies | Checked original registry archives for bytes 1.12.1 and reqwest 0.12.28 against Cargo.lock checksums, then compared all seven inspected source files to archive members. `Bytes::from(Vec<u8>)` takes over the payload allocation; `Bytes::clone` shares it (possibly allocating reference-count metadata); reqwest `Body::from(Bytes)` stores it as reusable bytes. The previous reqwest Vec-body conversion also used Bytes. No second payload copy is introduced along this conversion path. This is not a zero-allocation, zero transport-copy, or measured performance claim. |
| Read operations versus writes | REST GET may expose `None` body with resource/filter facts in URL/query. A JSON-RPC read is POST and exposes the complete JSON-RPC envelope. Policy must inspect binding and A2A operation plus the relevant decoded facts, rather than equating POST with write or `None` with no data release. No ToolRisk, idempotency, effect classification, or retry policy changes. Existing `A2aRemoteAgent` delivery validation still requires the configured write semantics. |
| Streaming / replay | Both `call_unary` and `call_stream` pass the snapshot. Existing attested `MessageIdReplay` calls `send_message_with_attempt` and therefore reaches the same unary snapshot/authorization path; it does not gain an authorization bypass. A2A operation distinguishes streaming send and subscribe. These three getters intentionally do not expose every HTTP header or add a new stream policy. |
| Anonymous / compatibility providers | Anonymous returns `Ok(None)` before constructing an authorization context and does not call a token provider. Existing providers may ignore all three getters; `StaticA2aBearerToken` does exactly that. They remain source-compatible, but do not acquire destination- or input-aware host policy. Existing immutable endpoint/security pin checks still apply. |
| Deadlines / dropped Future | The original absolute request deadline is created before serialization and reused for token resolution and send; the patch introduces no new clock or deadline. Dropping the call while authorization is pending drops its awaited Future before builder/send. A trusted provider can independently spawn work or retain a context; this client cannot cancel such work. The synchronous call to `provider.resolve` occurs before its Future is wrapped by `timeout_at`, so synchronous policy work must be bounded/cooperative, as now documented. This was also true before the patch. |
| Dispatch and uncertainty | `mark_dispatched` remains after authorization and builder construction and immediately before polling HTTP send. Denial/unavailability remains a pre-dispatch authorization error. Timeout/drop after the mark is conservatively treated as potentially dispatched by the durable Adapter; the flag does not prove bytes reached the peer. Existing Unknown/reconciliation behavior is unchanged. No additional business request, automatic retry or policy fallback appears. |
| Clone / retention / bytes limits | Existing public Clone remains. It now retains a shared immutable body and a cloned URL until every retained context is dropped; raw accessors also let trusted policy explicitly copy values. There is no total-retention, aggregate-memory, zeroization or provider-behavior guarantee. The existing serialization limit is on successful body length (16 MiB default, 32 MiB hard ceiling), not peak serializer allocation or retained Vec capacity, and is checked after serialization. These pre-existing allocation characteristics are not silently promoted into stronger limits. |
| Debug / secrecy | Manual Debug retains all previous fields and redacts the added URL and body, including avoiding body bytes/length in those two fields. Method is safe because it is selected internally. Existing remote tenant, task ID, scope names and attempt identifiers remain visible as before; do not call this whole context fully secret-free or fully redacted. No client-added bearer token is present in body facts. Deliberately supplied application data may contain secrets, which the raw getter exposes to trusted host policy by design. |
| Source / MSRV compatibility | Private fields prevent external struct literal construction. Public Clone/Debug implementations and the provider's existing signature/lifetime remain; the additions are getters and private storage. No Serde/wire shape changes. Existing dependencies already supply Bytes, Method and Url. New syntax and operations are available before Rust 1.88; checked package MSRVs are bytes 1.57 and reqwest 1.64.0. This is a static compatibility assessment, not an actual 1.88 build or downstream semver certification. |

## Remaining acceptance and smallest useful example

Public Interface tests still need to prove actual received method, percent-
encoded target/query and raw body bytes equal the callback observations for
both bindings; denial/unavailability, timeout/drop while policy is pending,
Anonymous and an unchanged legacy provider; streaming send and attested replay;
and absence of raw URL/body secrets from Debug. These are acceptance needs,
not claims of execution or findings that another agent's evolving tests omit them.

After those checks, the smallest useful compiled consumer example is one
host-owned `A2aBearerTokenProvider` dedicated to a reviewed destination. It
checks the complete destination/resource facts and bounded decoded body under
the known binding/operation, rejects unapproved release with PermissionDenied,
then obtains a separate short-lived token. It must show deny-before-send and
avoid logging raw facts, prefix-only URL matching, trusting remote tenant as
local authority, or interpreting a shape schema as consent. Reuse existing
bounded JSON and A2A types; no new generic parser, policy framework or owner is
needed. No example was implemented or compiled in this review.
