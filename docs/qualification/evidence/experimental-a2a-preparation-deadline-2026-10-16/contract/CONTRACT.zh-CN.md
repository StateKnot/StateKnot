本契约冻结待实现的「A2A 认证后输入与初始策略期限」切片；不修改旧 v2。来源、11 个入口、真实 JSON 路径与未执行的验收矩阵分别见 sources.json、entry-matrix.json、body-path-matrix.json、acceptance.json。本目录作者未实现生产/测试，也不对自己的契约声称独立审阅。

1. 原认证预算独立保留。认证成功后立即、仅一次建立服务器持有的 monotonic D = now + 原 request_timeout。实际 JSON body 读取、boundary 同步规范化/解码及 SDK decoded prepare 的初始 authorizer/admission 共用该 D，阶段之间不得重置。backend unary/stream 创建仍用原独立 request_timeout；既有订阅 idle/recheck 期限不变。这不是认证到响应流结束的端到端总时限。
2. 原 principal 与同寿命的私有 task-local deadline 由 boundary 持有；可信值不能来自 Header/body/task metadata。prepare 缺任何可信上下文必须 fail closed，不新建 fallback D。无需新增公开 API、配置项、依赖或权限。旧认证→解码/校验/能力检查→authorizer→admission→operation permit→backend 顺序保持；deadline/shutdown 检查只作为新增前置拒绝，不提前调用后续阶段。
3. 唯一限额层顺序调整：先安装 enforce_boundary，最后外包同一原 maximum_body_bytes 的 DefaultBodyLimit::max。Axum 0.8.9/axum-core 0.5.6 该层仅在 request extensions 插入 limit，不读取/解析 body；这样 middleware 与原 SDK 都看到同一配置，而非 early Bytes 隐含的 2,097,152 字节默认值。原配置上限/下限、所有其他限额及 admission 数量不变。
4. 只对实际 JSON 入口读取 body：REST message:send/message:stream 与 RPC 保持原 Limited.collect、规范化、错误 body 与移除 Content-Length 规则；新增 REST POST /tasks/{id}/pushNotificationConfigs 只做 Bytes::from_request(request, &())，经原配置 limit 收齐。push 成功用原 parts + Body::from(bytes) 还原；所有原 request headers（包括 Content-Length）、method/URI/version/extensions 和 payload bytes 保持，不 serde 再编码。push 的解析仍交原 SDK Json<Value>/ProtoJSON。GET/DELETE、POST cancel/subscribe、无匹配 JSON extractor 的 POST 与 discovery 不新增 body 读取。
5. push 提前读取错误仅经 axum::extract::rejection::JsonRejection::BytesRejection(err).into_response() 转换，不能套 RESTsend AIP413、手写未知 IO error 文本或改成统一 413。原长度超限是 plain 413 `Failed to buffer the request body: length limit exceeded`；原其他 body 错误是 plain 400，保留 source-dependent 完整原文本。旧 push SDK rejection 原经 boundary 的 apply_origin_header，新增 early push rejection 必须保留允许 Origin 的 ACAO/Vary；不能顺带改变 RESTsend/RPC 原 early-error 头。push 有限 malformed JSON 仍由 SDK 给原 plain 400 JsonSyntaxError；有效 JSON 但 Push ProtoJSON 无效仍给 SDK 原 AIP400。422 是 typed Json<T> 的数据错误，不把它伪写成 Json<Value> 的语法错误。
6. 真实 body await 与每个 initial policy await 都选择同 D 和 shutdown；进入前与返回后检查实际 shutdown/now>=D。观察到 shutdown 优先，其次已到 D，最后原结果；同时 ready 的成功或错误 callback 不能越过时钟检查获得后续权限。边界同步规范化返回后也检查；SDK 合法同步 decode 进入 prepare 前检查，不能因 CPU 工作晚返回继续策略。SDK 无效 decode 的终止拒绝保留原 map，不把 next.run 整体套 D，也不增加 phase-notify/后台监视任务。
7. body predecode 超时固定 HTTP408/plain `request timed out`，shutdown HTTP503/plain `service unavailable`；不伪造 RPC id、task resource 或 401。prepare 的 policy timeout 固定原 wire::A2AError::internal("A2A operation timed out")；shutdown 固定原 internal("A2A service is shutting down")。期限内 Forbidden/Rejected/Unavailable、能力/扩展/验证错误、overload 原 map 全部保留。初始 prepare 失败发生在 headers 前，REST 为完整原 SDK HTTP/AIP error（唯一 ErrorInfo timestamp 仅做 UTC 规范化），RPC 为原 HTTP200/原 id JSON-RPC error；不能复用已建立 SSE 的裸 error oracle。
8. pending body/callback future 由当前请求直接持有，不 spawn/detach/retry；超时、shutdown 或服务器实际 Drop 请求 future 时释放该 future。初始 policy 拒绝/超时/shutdown 在 operation permit 前终止，后续 admission/backend 计数按阶段保持为零；最终 guard 若在取得 permit 后观察到失活，必须立即退役该 permit、不得交给 backend。不能虚称这一分支从未瞬时 acquire；policy 尚在 pending 期间则不得占用 operation slot。紧邻 permit handoff 检查实际 clock/shutdown，晚完成的 callback 不授予权限。request permit 在初始错误响应完成或请求 future 实际 Drop 后释放；即使客户端保留第一份 error Response，cap1 第二健康任务仍可用。原订阅 permit/backend 生命周期不改。
9. 同步阻塞的 callback/decode 无法被 Tokio timeout 抢占；契约保证它返回后的拒绝，不承诺非合作代码的 wall-clock 响应上限。callback 已经提交到外部 quota 的副作用不由 Drop 回滚。TCP 断连的远端时间不等于服务端已经观察 Drop；验收必须观测实际 future Drop/counters，不承诺瞬时断连回收或零时隙撤销。

验收须用现有 subscription TCP fixture 的小扩展/私有 child 复用真实 server/service/probe。全部 11 operation × 2 binding 的两初始阶段 timeout、正常/原错误、原 principal/op/task/config tuple 必须覆盖；三 JSON 路径 slow-body、累计 body+policy D、真实 clock ready races、pending shutdown、request-cap1 复用、pending 期间 operation-cap1 无占用、configured max > 2MiB、原 push plain/AIP/headers/Content-Length/bytes 和忽略 body 行为都不可漏。具体唯一 oracle 见 acceptance.json；原 8 private + 1 TCP family/17×2 与完整原门禁继续保留。现在只冻结输入/验收口径，未运行 red/green、Cargo、TCP、Native、DB、Docker 或 CI。

本切片不触 SQL37 scopedJoin cleanup、metadata-only Root 捷径、完整 Rootauth、事务锁序、lease/fence/deadline/quantum、bounds/default stack；不授予持久 backend、真实 IdP/凭据再认证、stdio Linux owner 或外部 pilot 资格。R1 仍未完成。
