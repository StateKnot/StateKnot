# 独立状态耐久子 Run：事务存储与剩余运行时工作

状态：已实现核心契约、图内固定声明、只读准入准备，以及 PostgreSQL 原子归属/准入、预算预留和终态结算。
**自动 Join、取消传播和父级恢复尚未实现**，这里不是端到端子 Run 执行教程。完整设计与未决项见
[RFC-0004](rfcs/0004-durable-child-runs.md)。现有可用能力仍是
[共享状态静态子图](graph-composition.zh-CN.md)。另见
[英文说明](durable-child-runs.md)。

## PostgreSQL 事务存储（迁移 20）

这是可信存储层构件，不是自动子 Run 协调器。调用前必须完成调用方认证，以及
对具体声明槽位的委派授权。数据库连接池属于可信服务端；事务自定义设置用于
阻止旧版本 Worker 绕过新约束，**不是对不可信 SQL 用户的安全隔离**。

`PostgresStore::admit_child_run` 接收准备好的意图、父节点确切的物理开始记录、
父级 Worker 日志（`child-run-admitted`）、独立子准入日志/初始 Checkpoint，
以及与父级当前日志头一致的**直接消耗绝对累计值**。Schema 回调在写事务之前执行；
事务内部按以下顺序完成：

1. 串行化整棵树的派生/结算，再按根到父的顺序锁定祖先 Run。
2. 重验当前 Checkpoint、就绪激活、未完成的物理开始记录、不可变准入/声明、
   活租约、所有祖先的 Active 状态、深度/活跃后代上限及累计预算。
3. 一次提交新的子准入、初始 Checkpoint、不可变归属和审计事实、预算预留及父日志头。

不能接管或挂接已经存在的独立 Run。同一归属和派生摘要的重试先恢复原始身份，
再决定是否需要新准入检查；不同业务意图冲突。最多保留 256 个生命周期子项，
深度最多 32；已终态但尚未结算的后代仍占用活跃容量。这些不是吞吐指标。

首个存储配置将父级外部调用与受管子工作串行化：未完成的父级 Model/Tool 调用
阻止派生；未结算子项阻止父级新的 Model/Tool 修订。结算后允许恢复直接调用。
`InvocationBudgetProvider` 必须返回只扣除父直接消耗的余额；执行器再扣减已结算
子树消耗，并将确切账户摘要带入开始事务。旧的底层开始接口不能绕过这一步。
响应丢失后的恢复不会重新派发或重复计费。

所有终态写入都经过统一的子级账务校验。新成功/失败/取消路径的
`GraphLifecycleEvidenceProvider` 返回**直接消耗**，生命周期协调器只加一次子树消耗。
底层终态写入者必须提供完整子树总额，或先对可信直接消耗调用 `include_child_usage`。
日志头 CAS 与最终事务会再次验证；子级的局部拓扑峰值不会累加到祖先。

子级进入终态时，在它自己的事务中保存不可变生命周期、确切终态日志锚点和耐久通知，
**不锁父级或祖先 Run**。后续审计日志不会替换此锚点。`settle_child_run` 按
“树 → 父 → 子”锁定，一次替换预算预留、提交父结算日志（`child-run-settled`）并消费通知。
重试恢复原始结算事件；已确认超额照实记录，价格不明则继续保留预留，不能记为零。

`pending_child_settlements` 返回第一页，最多 16 个有界 Key；
`pending_child_settlements_after` 用上一页最后的 Key 继续，游标在该子项结算后仍可用。
应跳过暂时无法定价的项继续扫描，完整一轮后从头重扫：事务提交顺序不保证等于事件时间。
不能把时间戳当作永久投递水位。`load_child_run` 与 `load_child_budget_account`
会核对规范编码、归属、父/图 Pin、物理节点、Checkpoint/日志锚点以及结算绑定。

任何未结算子项都会阻止父 Run 进入终态或推进 Checkpoint。这不会伪造 Join、
计时器或用户中断。祖先取消后禁止继续派生，但自动取消投递及父级挂起/恢复尚未接入；
没有这些协调器时，不能把存储接口暴露为完整的子 Run 执行服务。

升级时先通过现有 `PostgresStore::migrate_database` 流程执行迁移，再启动兼容 Worker。
迁移 20 会为已存在的、声明子级能力的准入回填版本 1，新准入同样受保护；
旧 Worker 无法更新这些 Run，普通根 Run 保持兼容。启动核对迁移校验和、
约束/索引/触发器以及实际守卫函数体。有子数据后的回退方式是停止新派生，
由兼容 Worker 完成取消/恢复/结算；不能删除迁移、归属、预留或禁用守卫。

## 已实现的核心原语

运行离线示例：

```console
cargo run -p stateknot-core --example child_run_contracts --locked
```

示例验证合成 Checkpoint，构造并往返序列化 `ChildRunKey`，计算两个候选
分配后的剩余 Token，并拒绝超限的第三个分配。不会访问数据库或启动 Agent。

- `ChildRunSlot` 使用与 `NodeId` 相同的大小写敏感、最多 128 字节的语法。
  语法正确不等于已经在可执行图中声明。
- `ChildRunKey` 绑定完整父激活和槽位；更换物理尝试或租约不改变身份。
  反序列化拒绝未知字段并重新校验摘要。摘要不是授权证明或签名。
- `CumulativeBudgetReservation` 投影有限预算的全部累计维度，包括费用
  币种和 Token/调用子集。深度、并发、fan-out 等峰值及未知价格不得混入。
- `check_capacity` 校验“已结算用量 + 全部未结算分配 + 当前候选”，最多
  接受 256 项；重复项重复计入。该上限仅约束计算量，不是子 Run 派生上限。
  过期、未知费用、不受支持的币种及整数/金额溢出均拒绝继续。

上述核心原语是纯计算；下文 PostgreSQL 存储事务同时约束
父级直接开销与所有子级分配，绑定唯一归属、读取完整预留集合，并按真实
终态证据结算一次。绝不能把预留额写成已消费用量；子截止时间、权限、
祖先深度、活跃并发和 fan-out 仍需单独校验。

核心测试已覆盖身份和输入漂移、篡改、重试/接管稳定性、全部累计维度与
子集上限、费用未知、超限、溢出及顺序无关性。固定测试摘要为
`sha256:21da0ea8e1d1e20c7745a8a4f1794bffc6f42f7d62c24145db141c2dfb855a48`。
事务适配器已增加迁移 20；没有启用官网上的完整子 Run 能力声明。

## 已实现的预算账户状态转移

`ChildRunBudgetAccount` 是不可变的纯状态转移契约，**不是 PostgreSQL 账本，
也不是启动子 Run 的许可**。`new(parent, graph, direct_head, direct_usage)`
固定真实父准入、预算、图内生命周期子数上限和可信的直接用量观察，不会假定一个
已有 Run 尚未花费预算。恢复后通过 `validate_for` 重绑可信父准入与图；各项用量
是否完整、是否真实持久化，仍须存储适配器独立验证。

`reserve(intent, parent_graph, observed_at)` 重验节点声明，统一计算父级直接用量、
已结算子树和全部未结算预留。同逻辑归属与派生摘要的重试返回原先选定的子身份，
即使已经过期也不会重新分配；意图变化则冲突。不同归属不能复用同一子 Run ID。
已结算子项仍计入生命周期数量上限，不提供删除、循环复用或随意退款接口。

`ChildRunBudgetSettlement::new(admission, lifecycle, terminal_head)` 固定完整子身份、
准入与意图摘要、确切终态日志、状态、完整生命周期摘要及用量。只有成功、失败、
取消三种终态可结算。`settle(key, evidence)` 用真实用量替换一次预留；相同重试
不变，终态证据变化则冲突。失败和取消也照实计费。费用不明时保留未结算预留；
已确认超额或预算外币种则照实记账，后续容量检查阻止继续分配，绝不截断或抹掉
真实开销。截止时间已过不妨碍记录结算事实。

`observe_direct(head, usage)` 接受父级**直接消耗的绝对累计值**，不是增量，
也不能传入已经包含子树的总额。完全相同的重放不变；同日志头替换用量、旧日志头、
倒退时钟、其他 Run、任何计数或已知币种费用回退都被拒绝。直接消费超限或价格
不明时仍保留观察事实，但不能继续分配预算。

`accounted_usage` 只累加父直接用量和每个直属子 Run 的完整子树用量一次。
`delegated_usage` 通过 `BudgetUsage::cumulative_only` 排除子级局部深度、并发、
fan-out 峰值；子级峰值的最大值不能代表父级真实拓扑，后者仍由运行时单独观察
并强制约束。`remaining` 再加入全部未结算预留，要求时钟不早于保留的观察事实，
并检查溢出、过期、未知费用和额度。不能把投影余额当成实际消耗，也不能重复加孙级。

版本 `1` 的规范快照最多 256 个生命周期子项、8 MiB；读取数组时就检查数量，
适配器还须在解码前限制原始字节大小。账户按归属摘要排序，只用于账务完整性，
**不是 Join 归并顺序**。闭合编码重算摘要，域为
`stateknot.child-run-budget-account.v1\0`，后接将摘要字段设为 SHA-256(空字节)
的规范快照。终态摘要域为 `stateknot.child-run-budget-terminal.v1\0`，后接完整
生命周期规范编码。摘要只检测漂移，不是来源认证或授权。

数据库事务现已在父 Run 行锁下原子替换账户，并同步提交子归属、准入/结算；
父级直接调用开始时还会校验观察到的账户摘要。不能分别计算、分别保存快照。
账务结算不等于完成 Join，父 Run 仍需通过全部图完成和生命周期检查。

## 已实现的准入准备

### 固定在父图中的委派声明

```console
cargo run -p stateknot-core --example child_run_declarations --locked
```

通过 `CompiledGraph::with_child_runs(GraphChildRunPolicy)` 创建带委派声明的新图。
必须先声明，再绑定执行器、注册图和准入父 Run；修改已注册定义必须使用新的图身份/版本，
不能覆盖原有 Pin。没有声明的旧图不能委派，
但其原有规范编码和摘要保持不变。声明使用显式版本 `1`，拒绝未知版本和字段。

每个 `ChildRunDeclaration` 固定父节点、大小写敏感槽位、完整子 Agent 定义摘要、
子图以及输入/输出 Schema。`ChildAgentReference` 对完整规范化 Descriptor
使用域 `stateknot.child-agent-definition.v1\0` 计算摘要；即使 Agent 名称与版本
相同，指令、模型、工具或限制变化也会被识别。父声明只保存摘要，不复制私有指令。
摘要不是签名，也不能代替调用方授权。

每张图最多 256 个声明、每个节点最多 64 个槽位。规范顺序是 `(node_id, slot)`，
也是后续 Join 的归并顺序；传入顺序不改变图摘要。重复槽位、未知父节点、空声明、
超限和反序列化篡改均被拒绝；读取声明数组时即执行数量边界。

`ChildRunTopologyLimits` 明确限制：剩余后代深度 1–32、单 Run 生命周期内直属
子 Run 总数 1–256、同时未终结的全部后代数 1–256。叶子剩余深度为 0。
注册表在启动时解析全部目标，要求子图剩余深度严格小于父图；缺失目标或 Schema
漂移都会阻止启动。数据库现已原子检查活跃计数和每层祖先上限；已终态但尚未
结算的后代仍占用活跃容量。这些是安全边界，不是已经测得的吞吐承诺。

运行时两个准备接口都已校验父图声明；之前对未声明旧图的准备调用现在会拒绝。
需要注册带声明的新图并准入新父 Run，不能修改已经准入的旧图。底层核心调用方
必须同时执行 `validate_declaration` 和 `validate_for`；提交时的真实授权、租约、
余额与拓扑检查仍不能省略。

静态共享状态展开遇到委派声明会拒绝，不会丢失或重写归属；无调用的空展开则完整
保留原图。如需组合，先完成静态展开，再以最终节点身份声明独立子 Run。

### 不可变准备与重验

新增 `ChildRunAdmissionIntent`，保存父准入摘要、逻辑归属、候选子准入、
完整子图及私有初始状态。规范化信封最多 16 MiB，反序列化重新检查内部
作用域、图/Schema 引用、JSON 数值和摘要完整性。

`spawn_digest` 固定子 Agent 定义、图版本、输入、预算策略及解析结果、
授权证据、初始状态和就绪节点、父准入与槽位，以及 `cancel_and_join`
关闭策略。候选子 Run/thread/invocation ID 不进入重试摘要，但保留在信封
中并受子准入自身的摘要校验。仅更换这些 ID 不会被误判为另一项派生；
业务输入变化则产生不同摘要。此阶段不分配准入事件或初始 Checkpoint ID。

`ResolvedBudget::validate_narrowing` 检查全部预算维度、截止时间和币种
上限，不会默默截断。子主体必须与父主体一致，子 Scope 必须是父授予
范围的子集。这不等于所有 Scope 都可以转授：可信策略仍须授权具体
声明的槽位与子目标；首版不支持跨主体身份交换。

运行时 `DurableAgentAdmission::prepare_child` 接入冻结的可执行注册表，
`validate_child_preparation` 复核反序列化后的准备值。二者均为同步只读
方法，不创建 Run、租约、预留、日志或外部调用。方法的 Rust 文档包含
可编译用法，可通过 `cargo test -p stateknot-runtime --doc --locked` 验证。

检查包括：父快照 Active 且未隔离、当前 Checkpoint 指针一致、节点确实
就绪且激活输入由框架确定性派生、父准入完全匹配、父子可执行定义可用、
截止时间未过期，以及子输入/状态/授权证据通过本地 Schema。子状态可以
使用不同 Schema，不会隐式合并到父状态；同一 Run 的嵌套命名空间仍拒绝。

只读检查成功后仍可能发生取消或其他消费，不能当作耐久准入许可。未来
事务必须在锁内重验并检查活跃拓扑与全部预算预留；对已经提交的派生，
丢失响应后的证据查找必须先于新准入的截止时间和就绪检查。

新增真实 PostgreSQL 测试覆盖未创建子记录/未派发节点、候选 ID 重放、
注册表重建、Schema/部署拒绝、父取消后拒绝，以及 Graph Driver 提交真实
非初始 Checkpoint 后拒绝旧快照。这些不等于已经实现原子子 Run 执行。
固定派生测试摘要为
`sha256:64a2d833b22e3f017d502b4a1c30281ef44680c3c0a710399b1eec02c5d595b8`。

## 完整耐久子 Run 的目标契约（尚未全部实现）

存储层子 Run 已拥有独立 Run ID、状态、Checkpoint、租约和终态证据。父子关系
单独持久化；子 Run 内仍使用自己的根命名空间，不冒充已经实现同一
Run 内的嵌套命名空间。

- 父逻辑激活和声明的子槽位共同确定唯一归属。工作进程重启、物理尝试
  变化或租约接管不能创建第二个子 Run。
- 子准入、初始 Checkpoint、归属和预算预留必须在同一事务提交。
  不采用先创建子 Run、再记录父子关系的两步流程。
- 父级等待通过持久化 Join 释放工作租约；子终态与等待注册竞态不能
  丢失唤醒。结果按照声明的槽位顺序归并，而不是完成时间顺序。
- 首版只支持“取消并等待终态”，不支持脱离父级的后台子 Run。
  父级关闭后禁止新派生；有未终结的受管子 Run 时禁止父级进入终态。
- 子权限不得扩大父级可委托权限，子截止时间不得晚于父级；并发预算
  必须先预留、后按准确用量结算，不能给每个子级重复分配同一余额。
- 无法确定的外部调用用量不能记为零；取消请求也不能被当作外部操作
  已经停止的证明。保留预算预留并暴露待恢复状态。

## 实施顺序与验收

1. 核心身份、声明、预算契约：严格反序列化、固定摘要、边界和篡改测试。
2. PostgreSQL 原子派生：归属唯一性、并发预算、响应丢失重试、过期租约
   拒绝，以及从当前迁移 19 升级的验证。
3. 生命周期：终态绑定、Join 唤醒、持久化取消传播、所有关闭路径的守卫，
   以及不重复结算。
4. Runtime：独立调度、挂起恢复、注册表重建和可执行示例。
5. PostgreSQL 16/17 故障恢复与完整 CI；通过后更新中英文教程和官网，
   再启用该能力。

必须覆盖派生提交前后、终态提交与通知之间、等待注册前后、结算提交后
响应丢失，以及更高租约接管等中断点。数据库层必须保护旧工作进程不能
绕过父级关闭约束；不能仅靠新的 Rust 接口维持安全性。

## 尚未冻结的决策

剩余工作是专用 Join 控制、释放租约的等待/恢复、持久化取消传播、完整运行时
集成和可测量的恢复/容量指标。存储层完成不代表上述闭环已经可用；草案不会
作为完整已实现能力发布到官网状态页。
