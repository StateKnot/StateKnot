# 独立状态耐久子 Run：开发契约

状态：已实现核心身份与累计容量计算；耐久子准入、归属存储、Join 和取消
尚未实现，不是子 Run 执行教程。完整设计与未决项见
[RFC-0004](rfcs/0004-durable-child-runs.md)。现有可用能力仍是
[共享状态静态子图](graph-composition.zh-CN.md)。另见
[英文说明](durable-child-runs.md)。

## 已实现的核心原语

运行离线示例：

```console
cargo run -p stateknot-core --example child_run_contracts --locked
```

示例验证合成 Checkpoint，构造并往返序列化 `ChildRunKey`，计算两个候选
分配后的剩余 Token，并拒绝超限的第三个分配。不会访问数据库或启动 Agent。

- `ChildRunSlot` 使用与 `NodeId` 相同的大小写敏感、最多 128 字节的语法。
  语法正确不等于已经在可执行图中声明。
- `ChildRunKey` 绑定完整父激活和槽位；更换物理尝试或租约不改变身份。
  反序列化拒绝未知字段并重新校验摘要。摘要不是授权证明或签名。
- `CumulativeBudgetReservation` 投影有限预算的全部累计维度，包括费用
  币种和 Token/调用子集。深度、并发、fan-out 等峰值及未知价格不得混入。
- `check_capacity` 校验“已结算用量 + 全部未结算分配 + 当前候选”，最多
  接受 256 项；重复项重复计入。该上限仅约束计算量，不是子 Run 派生上限。
  过期、未知费用、不受支持的币种及整数/金额溢出均拒绝继续。

这些是纯计算，不是数据库预留或结算接口。未来存储事务必须同时约束
父级直接开销与所有子级分配，绑定唯一归属、读取完整预留集合，并按真实
终态证据结算一次。绝不能把预留额写成已消费用量；子截止时间、权限、
祖先深度、活跃并发和 fan-out 仍需单独校验。

核心测试已覆盖身份和输入漂移、篡改、重试/接管稳定性、全部累计维度与
子集上限、费用未知、超限、溢出及顺序无关性。固定测试摘要为
`sha256:21da0ea8e1d1e20c7745a8a4f1794bffc6f42f7d62c24145db141c2dfb855a48`。
本增量没有新增数据库迁移或官网能力声明。

## 本阶段的交付边界

子 Run 拥有独立 Run ID、状态、Checkpoint、租约和终态证据。父子关系
单独持久化；子 Run 内仍使用自己的根命名空间，不冒充已经实现同一
Run 内的嵌套命名空间。

- 父逻辑激活和声明的子槽位共同确定唯一归属。工作进程重启、物理尝试
  变化或租约接管不能创建第二个子 Run。
- 子准入、初始 Checkpoint、归属和预算预留必须在同一事务提交。
  不采用先创建子 Run、再记录父子关系的两步流程。
- 父级等待通过持久化 Join 释放工作租约；子终态与等待注册竞态不能
  丢失唤醒。结果按照声明的槽位顺序归并，而不是完成时间顺序。
- 首版只支持“取消并等待终态”，不支持脱离父级的后台子 Run。
  父级关闭后禁止新派生；有未终结的受管子 Run 时禁止父级进入终态。
- 子权限不得扩大父级可委托权限，子截止时间不得晚于父级；并发预算
  必须先预留、后按准确用量结算，不能给每个子级重复分配同一余额。
- 无法确定的外部调用用量不能记为零；取消请求也不能被当作外部操作
  已经停止的证明。保留预算预留并暴露待恢复状态。

## 实施顺序与验收

1. 核心身份、声明、预算契约：严格反序列化、固定摘要、边界和篡改测试。
2. PostgreSQL 原子派生：归属唯一性、并发预算、响应丢失重试、过期租约
   拒绝，以及从当前迁移 19 升级的验证。
3. 生命周期：终态绑定、Join 唤醒、持久化取消传播、所有关闭路径的守卫，
   以及不重复结算。
4. Runtime：独立调度、挂起恢复、注册表重建和可执行示例。
5. PostgreSQL 16/17 故障恢复与完整 CI；通过后更新中英文教程和官网，
   再启用该能力。

必须覆盖派生提交前后、终态提交与通知之间、等待注册前后、结算提交后
响应丢失，以及更高租约接管等中断点。数据库层必须保护旧工作进程不能
绕过父级关闭约束；不能仅靠新的 Rust 接口维持安全性。

## 尚未冻结的决策

精确的 Rust/SQL/版本化编码、与现有账本兼容的多维预算预留、全部终态
写入路径及锁顺序、混合版本升级守卫、深度和派生数上限，以及实际容量
指标仍需通过实现验证。草案不会作为已实现能力发布到官网状态页。
