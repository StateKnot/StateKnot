# 耐久失败关闭

[English](failure-close.md)

PostgreSQL/runtime 配置现在可以固定原始失败、停止父任务派发、排空子任务，最后
以同一个失败和精确用量提交 Failed。这**不是取消，也不是立即完成失败**。
完整耐久子 Run 生产配置仍需运营、进程终止、角色隔离和容量验收。

## 可用边界

注册要求 Active Run、确切当前 Checkpoint、有效执行 fence，当前 fence 没有未完成
物理节点，当前 Checkpoint 没有未结清的直接模型/工具调用。可信证据提供者必须返回
**完整、已定价、累计的父级直接用量**，不包含子级，且包括先前尝试和 Checkpoint
恢复得到的副作用费用。存储层验证它不小于已观测直接用量，但不会替应用推算价格，
也不能凭空证明任意外部副作用的证据已完整。

直接证据不可用或含未知价格时，整个注册被拒绝，不释放恢复租约。宿主必须继续正常
的 fence 约束下副作用/费用恢复，不能丢弃工作、填零或无休止重试错误快照。
Waiting Run 和任意父级不确定副作用不被强制纳入本配置。子级费用未知时可以保留
关闭决定，但不能结算和最终关闭；已知超额仍须完整记录，不能裁剪到预留上限。

## 执行与宿主接入

冻结含子级的可执行注册表前，调用 `register_standard_run_failure_close_event_schema`。
`DurableGraphLifecycle::new` 在启动时检查确切离线 Schema。含子级图遇到终止性阻塞
后，生命周期协调器固定失败证据并返回 `GraphBarrierLifecycleOutcome::FailureClosing`；
`DurableAgentLoop` 返回 `AgentLoopOutcome::FailureClosing`。此时必须停止在已释放
fence 上派发工作。普通图继续使用原有的直接失败终态路径。

并行调度 `DurableRunFailureCloser`、`DurableChildReconciler`、独立取得租约的子任务
执行/清理，以及到期维护器。关闭器仅需 Store、冻结后的 Schema 注册表和有限的
`DurableGraphLifecycleOptions`，不会重新调用原证据提供者。类型的 Rustdoc 提供
经编译验证的配置与 tick 示例；构造函数不会自动启动后台任务。

即使租户没有可运行的父任务，也应公平调度 `tick(authorized_tenant, cursor, shutdown)`。
每轮至多 16 个候选，每项 1–10 次有限变更尝试；默认 3 次、初始 25 ms 指数退避，
最多 1 秒。重试保持同一事件 ID。逐项检查结果，单个阻塞/隔离任务不阻止后续候选。
发生逐项错误也保留 `RunFailureCloseSweepCursor`；短页自动开始下一轮扫描。
进程丢失后从 `None` 重扫，不使用单向永久水位。跨租户游标被拒绝；停机不会抹掉
尚待处理或提交结果不明确的耐久工作。

关闭期间核心业务生命周期仍是 Active，但可运行/到期发现排除它，直接领取租约也
会失败。用 `load_run_failure_close` 读取明确的待关闭/已完成状态；既有核心生命周期
和 Agent 快照序列化协议不变。宿主公开状态接口需要明确翻译这一状态，不能把父任务
报告成仍在执行或已经终止。

## 原子性、竞争与记账

迁移 24 新增不可变规范化意图，包含校验和、Checkpoint、Active 生命周期见证、
完整原始 Failure、冻结直接用量和确切 worker 日志锚点。注册在父 Run 行锁下与
spawn/生命周期写入串行化：事件、决定、全部直接未结算子级的取消工作和父租约释放
**在同一事务提交**；最终写入处重新检查数据库时钟，租约过期则全部回滚。
事务内不调用 provider、不执行子任务，也不获取祖先锁。

注册后不能再领取父租约、新增子级槽位、推进 Checkpoint 或改成竞争的取消/成功
结果。最先提交的决定胜出。逻辑重试在新的租约/日志头检查前返回原始 `Existing`
证据，这不代表后来提出的另一个失败与原失败相同。隔离仍可用，会阻止新的最终提交。
先前已经取消或终止的 Run 拒绝新失败注册；到期维护返回 `FailureClosing`，不覆盖原因。

子级取消复用现有耐久队列，验证 Active 失败关闭见证，使用公开安全的
`child.parent_failed` 原因，不复制父级私密诊断。送达不等于清理确认。子级已有自己的
失败关闭时保留自己的决定，取消送达继续待处理；子级真正终止后，下一轮记录真实
终态回执并且只结算一次。

最终提交把已验证、已结算的子级子树费用加到冻结直接用量，**仅一次**，原子提交
Failed 和关闭完成时间。统一终态记账路径拒绝改变直接用量，包括低层通用控制面写入。
数据库守卫比对完整原始 Failure，不仅是 ID。源证据在审计日志头变化、连接/协调器
重建、最终完成和重复调用后仍可恢复。

## 部署与验证证据

已发布迁移 1–23 和 Schema 不变；迁移 24 不为既有 Run 伪造失败意图。启动检查
确切迁移校验和、字段、约束、有效索引、启用的触发器和函数体。事务能力标志阻止
已连接旧写入器修改失败关闭 Run；新的子级协调器才能理解 Active 源见证。
这些是可信服务端连接池的混合版本守卫，**不是 SQL 角色认证**。应在受控窗口升级，
有保留的关闭证据时不能直接降级。

真实 PostgreSQL 测试覆盖源/最终写入回滚、捕获队列后租约过期、保留原始原因、未知
用量、篡改终态用量、重建 worker/handoff、子级自身失败关闭、17 项分页、租户/停机/
隔离，以及含数据 v23 SQL 升级和 catalog 漂移。独立的
[进程强制终止验收](process-kill-qualification.zh-CN.md) 在六个已提交的排空/重放
边界真正终止所属 OS 进程，并核对完整日志、生命周期和账目。这不代表提交前/中
的进程故障或真实 provider 认证。独立的
[COMMIT 丢失与 fence 配置](commit-loss-qualification.zh-CN.md) 增加源注册的请求/
响应截断及更高 epoch 接管后旧进程拒绝写入的验收。完整子级执行配置仍需组合进程终止、故障切换/恢复演练、
provider 副作用与费用恢复、SQL 角色隔离，以及长历史下完整扫描延迟和容量实测。

宿主应监控最老待关闭时间、整轮扫描延迟、未知副作用/费用、子级取消/结算滞后、
隔离和重试耗尽。不能通过手动标记已结算或改写失败来清除告警。本版本不承诺硬性
关闭延迟 SLA。
